# Призрак победителя — «Банки», 20.10.2026

Роль первого собравшего: маленькая прозрачная копия выбранного персонажа, крестики на глазах, волнистый хвост, след и дымка. Две серверные перестановки за матч, одна за ход, интервал 8 с, радиус 6 м, запрет в последние 3 с и после принятого подтверждения.

## Проверки

- Unity 6000.3.11f1, Synty 8198/8198 по путям и GUID перед запуском.
- `editmode-circus.xml`: 64/64 PASS — новая роль, спуск клеток, безопасность пола, приватность полок, финал и ограничения действий.
- `editmode-all.xml`: 799/801 PASS. Два сбоя: `ConsolePresentationTests.EveryCatalogGameHasDistinctCoverAndShortDescription` (карточка «Комары» отсутствует) и `UnifiedMinigameUiTests.EveryMinigameUsesSharedResultsAndExactlyOnePause` (в Mosquitoes нет общей панели результатов). Сцена Mosquitoes, ConsoleArtwork и MinigameCatalog побайтно совпадают с базовым main; эта задача их не меняет.
- `build.json`: macOS Development, Succeeded, 0 ошибок и предупреждений в BuildSummary. В Editor Console отдельно остаётся диагностика Addressables `ProfileValueReference: GetValue called with empty id`; она не прерывает сборку. При завершении Player встречается существующая диагностика native allocations.
- `client.txt`: хост и два клиента, призрак принадлежит клиенту; 75±20 мс UDP-задержки в каждом направлении, финальная сборка; 3/3 PASS. Дополнительно проверены появление перед клеткой, широкий обзор полёта и восстановление исходного FOV.
- `host-latency.txt`: призрак принадлежит хосту; по 75±20 мс реальной UDP-задержки в каждом направлении; 3/3 PASS.
- `disconnect-latency.txt`: клиент-призрак выходит после первой пакости; оба оставшихся процесса проходят проверку, выход владельца ожидаемый; 3/3 PASS.

Стенд проводит настоящие RPC и репликацию NGO. Он ускоряет подготовку и задаёт ответ победителя на сервере; движение выполняется через существующий ввод, подтверждения жертвы идут через обычные RPC. Проверяются одинаковые две изменённые позиции на трёх машинах, отказ чужому отправителю, два заряда, отказ третьему запросу, устаревшая ревизия ответа → открытая полка → принятый исправленный ответ, остановка роли при выходе, очистка при Results и восстановление исходного motor/rigidbody.

На скриншотах длительность окна выставления увеличена стендом. Реальное окно игры остаётся из конфигурации. Сетевые сценарии хоста и выхода выполнены перед заключительной правкой точки появления и локального обзора. После неё клиентский сценарий с задержкой повторён на финальной сборке; сетевые правила не менялись.

## Повтор

Собрать Development через `Igruha.EditorTools.AutotestBuild.BuildMac`, затем:

```sh
python3 tools/check_cans_ghost.py --scenario client --graphics-client 1
python3 tools/check_cans_ghost.py --scenario host --graphics-client 2 --latency-ms 75 --jitter-ms 20
python3 tools/check_cans_ghost.py --scenario disconnect --latency-ms 75 --jitter-ms 20
```

Это автоматическая проверка на localhost с искусственной задержкой. Живой плейтест на разных компьютерах, оценка полёта и баланс двух пакостей остаются за игроками.
