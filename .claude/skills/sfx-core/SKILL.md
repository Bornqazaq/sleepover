# Общий звук — слой Core

> **Opus 5 / high.** Код общий, ломается у всех пятнадцати игр сразу.
> Разметка поверхностей и прогон по сценам — `Sonnet 5 / medium`.

Цель: персонаж и интерфейс звучат одинаково во всех играх, а мини-игре остаётся
только её собственное. Всё, что может понадобиться второй игре, живёт здесь.

## Что уже сделано и работает

| Что | Где | Состояние |
|---|---|---|
| Движок звука: пул, вариации, лимит копий, несколько библиотек | `Core/Audio/MinigameAudioPlayer.cs` | готово |
| Шаги по расстоянию, поверхность под ногами, присед тише | `Core/Audio/CharacterFootsteps.cs` | готово, стоит на `Player.prefab` |
| Прыжок, приземление, падение тела, полученный удар | `Core/Audio/CharacterAudio.cs` | готово, стоит на `Player.prefab` |
| Метка поверхности на геометрии | `Core/Audio/SurfaceAudio.cs` | готово, **сцены не размечены** |
| Дверь, провал, рычаг | `Core/Audio/TrapAudio.cs` | готово, **на ловушки не повешено** |
| Наведение и щелчок в меню | `Core/Audio/UiAudio.cs`, `UiButtonSound.cs` | готово, **на экраны не поставлено** |
| Имена слотов | `Core/Audio/CoreSfx.cs` | готово |

Незакрытое из этой таблицы — и есть обычная работа этого скилла.

## Разметка поверхностей — главная оставшаяся работа

Без метки пол считается бетоном. Это честный звук для блокаута, но в готовой
сцене он врёт: по ковру хаба и по траве фермы персонаж топает бетоном.

Порядок на сцену:

1. Открыть сцену, найти геометрию пола.
2. На объект с коллайдером (или на его родителя — метка ищется вверх по
   иерархии) повесить `SurfaceAudio` и выбрать `SurfaceKind`.
3. Один компонент на павильон, а не на каждую доску.
4. Поверхность, которой нет в `SurfaceKind`, не выдумывать: список равен пачкам
   файлов в `Audio/Core/Character`. Нужна новая — сперва просить звук.
5. Особый звук шага в сцене (каменный зал, мокрый пол) — поле
   `stepSlotOverride` на метке. Слот при этом должен быть виден проигрывателю
   персонажа: мини-игра подкладывает свою библиотеку через
   `MinigameAudioPlayer.AddLibrary` при спавне.

Соответствие поверхностей и сцен — в `INTEGRATION.md` поставки, колонка «Когда
играет». Ковёр — хаб и казино; дерево — лестница хаба, клетки цирка, школа;
бетон — стройка, башня Duck Hunt, зал ангелов; металл — плиты «Рейса на память»;
трава — ферма Duck Hunt и двор «Заражения»; гравий — стройка и пока песок;
снег — зимние этажи Duck Hunt.

## Ловушки

`TrapAudio` вешается на объект ловушки и сам находит её тип:

- `DoorTrap.ClosedChanged(true)` → хлопок двери;
- `CollapsingFloorTrap.OpenChanged` → провал, **и на возврат тот же звук**;
- `TrapBase.Fired` при заполненном поле `lever` → рывок рычага.

Проигрыватель берётся арены, а не персонажа: ловушка стоит на месте и слышна
из своей точки.

## Интерфейс

Экраны проекта собираются редакторными билдерами и пересобираются целиком,
поэтому компоненты звука расставляются проходом, а не мышью:

```
Igruha/Арт/Озвучить интерфейс сцены
```

Проход заводит объект `UiAudio` с библиотекой `Core/UI` и вешает
`UiButtonSound` на каждую кнопку. Повторим — гонять после каждой пересборки
экрана. Наведение ловится само, через выделение в `EventSystem`.

Разделить смыслы вручную после прохода: «Назад» и Esc — `SFX_UI_Back`,
заблокированная кнопка — `SFX_UI_Error`, переключатели — `Toggle_On`/`Toggle_Off`,
ползунок громкости — `Slider_Tick` на каждый шаг, вкладки — `Tab_Switch`.

## Правила, которые нельзя нарушить

- **Шаг не вешать на animation event.** Клипы бега восьмерых заморожены
  (раздел 0 `igruha/CLAUDE.md`), правка клипа ради звука — молчаливая правка
  замороженного. Шаг отмеряется пройденным расстоянием.
- **Префабы персонажей трогать только добавлением компонентов звука.** Габариты,
  рост, аниматор, клипы, ростер, клавиши — не читать и не писать. Ставится всё
  на базовый `Player.prefab` командой `Igruha/Арт/Поставить звук персонажу`;
  восемь персонажей — его варианты.
- **Звук вешать на событие, которое поднимается на каждой машине.** Нокдаун
  реплицирован — годится; замах бьющего поднимается только у бьющего — не годится.
  Своих RPC ради звука не заводить.
- **Общее — в `Core/`.** Если звук может понадобиться второй игре, его место здесь.
  Правку `Core/` — отдельным мелким коммитом и с предупреждением напарнику в
  топик `warnings` до мерджа.

## Проверка

1. `refresh_unity` → `read_console` (errors) — компиляция чистая.
2. Прогон в плей-режиме: войти, дать ботам побегать, посмотреть, что слоты
   резервируются. Через мост это видно в статическом поле
   `MinigameAudioPlayer.slotReleaseTimes` — отметки времени растут, пока кто-то
   бегает. Предупреждений «В библиотеке нет слота» быть не должно.
3. На слух — уже пользователь: одинаково ли звучит в двух разных мини-играх.
