# Фаза 1 — Тикеты в Linear

> **Sonnet 5 / medium.** Механическая работа — разложить готовую спеку по шаблону и залить в Linear. Opus здесь не нужен, зря сожжёт лимит; `high` тоже ничего не добавит, только задержит ответ.

Цель: эпик в Linear, разбитый на тикеты, каждый из которых **можно взять и сделать, ничего не переспрашивая**.

Аргумент — название мини-игры.

## Куда пишем
- Команда: `IGRUHA` (`ee817979-1299-4f01-b14d-211e47036151`)
- Проект: `Комната (Party-game)` (`661991fb-22fa-4d42-929d-89a2e0f1b60e`)
- Инструменты: `mcp__linear__save_issue`, `mcp__linear__list_issues`, `mcp__linear__create_issue_label`

## Шаги

### 1. Проверить вход
Спека `docs/minigames/<игра>.md` со статусом «согласовано» и пустым разделом 11. Если есть открытые вопросы — вернуться в `/mg-spec`, тикеты не нарезать.

### 2. Проверить, нет ли уже эпика
`list_issues` по названию игры. В роадмапе уже заведены черновые эпики EPIC 8–21 с грубыми подзадачами — **не плодить дубли**, а дополнять и переписывать существующие тикеты по формату.

### 3. Создать/обновить эпик
Родительская issue: `[EPIC N] <Название> — <тип>`. В теле — суть игры за абзац, ссылка на спеку, состав фаз, Definition of Done из раздела 12 спеки.

### 4. Нарезать тикеты по фазам
Порядок фиксированный. Каждый тикет — подзадача эпика (`parentId`), 0.5–1 день. Тело — строго по `docs/templates/TICKET_TEMPLATE.md`.

**Фаза «каркас» (`phase:skeleton`)** — типовой набор, адаптировать под игру:
1. Сцена + арена из примитивов (по разделу 3 спеки), спавны, границы/KillZone
2. `MinigameDefinition` (ScriptableObject) с числами из раздела 8, регистрация сцены
   в Build Settings/Addressables и **добавление игры в `MinigameCatalog`** — без этого
   её не будет на экране приставки, то есть в игру не попасть
3. Контроллер игры — наследник `MinigameControllerBase`, фазы раунда
4. Каждая уникальная механика — **отдельным тикетом** (по разделу 4 спеки)
5. Расширения Core, если нужны — **отдельными тикетами**, помеченными `core-loop` (их видит и напарник)
6. Условие конца + расстановка мест для всех игроков (раздел 6)
7. UI мини-игры: таймер, счёт, подсказки, экран результатов
8. Интеграция: `IMinigame` → `SessionManager`, начисление очков
9. Смешные механики из раздела 7
10. Соло-прогон 2/4/8 болванок без ошибок

**Фаза «сеть» (`phase:net`)** — по разделу 10 спеки:
11. Состояние раунда → `NetworkVariable`, авторитет сервера
12. Действия игрока → `ServerRpc` с валидацией на сервере
13. Уникальные объекты игры (снаряды, двери, ловушки) под сервером
14. Дисконнект: обычного игрока и игрока с уникальной ролью
15. Тест host + client: картинка и результат совпадают

**Фаза «арт» (`phase:art`)** — **строго по подфазам `/mg-art`, один тикет на подфазу.**
Не сваливать арт в три-четыре крупных тикета: именно так на Duck Hunt звук уехал
в долг и остался там, а запекание не сделали вовсе — и сцена выпала из сборки
с 73 ошибками. Подфаза без тикета = подфаза, которую не сделают.

16. **4.0 Разведка и арт-бриф** — раздел 14 спеки написан и утверждён геймдизайнером,
    паки подобраны, таблица «что чем одеваем» готова. Ворота: без «да» дальше нельзя
17. **4.1 Дресс** — `Scripts/Editor/<Игра>Dress.cs` поверх блокаута через `DressKit`,
    габариты замеряются, коллайдеры моделей срезаются
18. **4.2 Палитра и поверхности** — материалы URP, цвет усреднением по UV мешей пака,
    большие плоскости на материале, а не на моделях
19. **4.3 Окружение и свет** — декор без единого коллайдера, запретные зоны, свет кодом
20. **4.4 VFX** — на существующие сетевые события игры, `Core/` не трогается
21. **4.5 Звук** — отдельным тикетом всегда: в меш-паках Synty аудио нет вовсе
22. **4.6 Запекание и приёмка** — `Tools/Арт/Запечь арт сцены`, ноль ссылок на
    `Assets/Synty/**`, бинарники в LFS, замеры приёмки сошлись

Если игре нужны **новые клипы или правки аниматора** — это отдельный тикет
с пометкой ⚠️ и явным гейтом на согласие геймдизайнера: аниматоры и клипы
заморожены (`igruha/CLAUDE.md`, раздел 0), а билдер контроллеров общий на всех
восьмерых персонажей. В подфазы 4.x такой тикет не входит.

**Фаза «плейтест» (`phase:playtest`)**:
21. Плейтест 2–4 живых игрока, правка game feel и чисел в конфиге

### 5. Проставить связи и лейблы
- `parentId` на эпик, «Зависит от» в теле тикета.
- Лейблы фазы (`phase:skeleton` / `phase:net` / `phase:art` / `phase:playtest`) + области (`minigames`, `core-loop`, `art`, `network-spike`). Если лейбла фазы нет — создать через `create_issue_label`.
- Приоритет: каркас — High, сеть — High, арт — Medium, плейтест — Medium.
- Статус: первый тикет каркаса — `Todo`, остальные — `Backlog`.

### 6. Отчитаться
Показать пользователю список созданных тикетов: ID, заголовок, фаза. Обновить `STATE.md` — строку этой игры в таблице раздела 3.

## Чего не делать
- Не создавать тикеты «написать класс X» — тикет описывает **поведение**, которое появится в игре.
- Не смешивать фазы в одном тикете (кроме явно связанных мелочей).
- Не хоронить правки Core внутри тикета мини-игры — напарник должен видеть их отдельно.
