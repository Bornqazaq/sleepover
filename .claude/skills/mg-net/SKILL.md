# Фаза 3 — Сеть (NGO, авторитет сервера)

> **Opus 5 / xhigh.** Сетевые баги самые коварные — рассинхроны, гонки, «у хоста работает, у клиента нет». Лестница эскалации, если засели: `xhigh` → `max` → **Fable 5**. `max` не всегда даёт прирост и склонен переусложнять, поэтому не начинать с него. Fable 5 — последняя ступень: дороже вдвое и думает дольше, зато берёт то, что не берётся.

Цель: игра работает на host + client, состояние совпадает у всех, клиент не может подтасовать исход.

Аргумент — название мини-игры.

## Вход
Каркас фазы 2 закрыт: игра проходится в одиночку без багов. Если нет — сеть не начинаем, она умножит существующие баги.

Прочитать раздел 3 `igruha/CLAUDE.md` и раздел 10 спеки (сетевая модель).

## Разделение на три ведра

Пройти по всей логике мини-игры и разложить:

| Ведро | Куда | Признак |
|---|---|---|
| **Состояние** | `NetworkVariable` | должно быть одинаковым у всех: фаза, таймер, счёт, прогресс, жив/мёртв, чья роль |
| **Действие игрока** | `ServerRpc` | клиент шлёт намерение → сервер **валидирует** → применяет |
| **Событие-оповещение** | `ClientRpc` | «выстрел произошёл», «дверь закрылась» — только для эффектов, не для состояния |

Локальным у клиента остаётся только: ввод, визуал, звук, предсказание собственного движения.

## Чеклист миграции

- [ ] Контроллер мини-игры — `NetworkBehaviour`, состояние раунда в `NetworkVariable`
- [ ] Все точки изменения важного состояния из фазы 2 обёрнуты в `if (!IsServer) return;`
- [ ] Каждое действие игрока идёт через `ServerRpc`, и **сервер проверяет право на действие**: та ли роль, жив ли, в зоне ли, не в кулдауне ли, хватает ли ресурса. Не доверять клиенту ничего.
- [ ] Весь рандом — только на сервере
- [ ] Определение мест и начисление очков — только на сервере, через `SessionManager`
- [ ] Сетевые объекты спавнятся только на сервере (`NetworkObject.Spawn()`), префабы зарегистрированы в `DefaultNetworkPrefabs`
- [ ] Состояние не гоняется повторяющимися RPC — только `NetworkVariable`
- [ ] Никаких аллокаций и тяжёлых операций в сетевых update-циклах
- [ ] Позднее подключение / переподключение не ломает состояние раунда

## Дисконнекты — проверить явно

- [ ] Обычный игрок вышел посреди раунда → матч продолжается, его место засчитывается по правилу из спеки
- [ ] Игрок с уникальной ролью (охотник / ведущий / оператор) вышел → поведение по разделу 10 спеки (передать роль, завершить раунд, заменить ботом — что решено)
- [ ] Хост вышел → все корректно выходят, без краша

## Тест на стенде
Предпочтительно **Multiplayer Play Mode** (IGR-275) — два инстанса без сборки билдов. Если не настроен — настроить, это окупается на каждой следующей мини-игре.

Сценарий приёмки:
1. Host + client, пройти раунд целиком.
2. Сверить у обоих: таймер, счёт, кто где, кто победил, итоговые места.
3. Проверить, что клиент не может выполнить чужое действие или действие вне своих условий.
4. Прогнать дисконнект-кейсы выше.
5. Консоль обоих инстансов чистая.

## Живой прогон на разных машинах — обязателен

> **Стенд не заменяет живой прогон.** У «Ангелов» стенд показал зелёный свет и фаза считалась закрытой, а первая же катка на трёх настоящих машинах вскрыла пять багов, включая два блокера. Пока живой прогон не состоялся, фаза не закрыта.

**Почему стенд слеп.** Оба инстанса MPPM делят один процесс, одну файловую систему и одну машину. Не воспроизводятся ровно те баги, что живут «по машине на игрока»:

- состояние, которое считает только владелец (у чужих копий мотор выключен, и на сервере тоже) — присед, любые локальные визуальные трюки;
- UI, привязанный не к своему аватару: на стенде «первый в списке» и есть твой игрок, на клиенте — уже нет;
- роль или блокировка, забытая при смене сцены: персонаж переезжает живым, и в хаб уезжает вместе с ролью;
- всё, что зависит от разных билдов и платформ.

**Симптом, который надо узнавать в лицо:** «не работает у одного человека из всех». Это почти всегда состояние, привязанное к машине, а не общий баг игры. Первым делом смотреть, чем этот игрок отличался — роль, персонаж, кто хост.

### Как поднимается прогон

Связь — **Tailscale**, не проброс портов: у половины домашних провайдеров CGNAT, пробрасывать нечего. Даёт каждой машине постоянный адрес `100.x.x.x`, одинаково работает и в одной квартире, и из разных домов. Бесплатный план — до 6 пользователей, устройств неограниченно.

- Все ставят Tailscale и **принимают приглашение организатора**. Быть в списке Users мало: нужно устройство в сети. Проверка — `tailscale status` у организатора показывает их машины, `tailscale ping <адрес>` отвечает.
- Организатор узнаёт свой адрес (`tailscale ip -4`) и **вписывает его в `host.txt` внутри архивов до раздачи** — участнику вводить нечего.
- Хост поднимается **первым**, остальные в пределах пары минут.

### Требования к билду

- [ ] `ServerListenAddress = 0.0.0.0` в `Boot`. С `127.0.0.1` хост не принимает никого извне
- [ ] Адрес хоста берётся из аргумента `--host <ip>`, а не зашит в сцену (`NetworkLaunchArguments`)
- [ ] Ярлыки запуска рядом с игрой: клиент и хост отдельно. **Имена файлов латиницей** — zip с macOS не ставит флаг UTF-8, и Проводник Windows покажет кириллицу как `╨ÿ╨ô╨á╨É╨ó╨¼.bat`
- [ ] `README.txt` для Windows — с BOM, иначе Блокнот покрошит кириллицу внутри
- [ ] Ожидание состава — сотни секунд, не десятки: люди запускают игру вразнобой. 15 с хватает только стенду
- [ ] **Addressables собраны под каждую платформу отдельно.** Проверять не «сборка прошла», а наличие `.bundle` в `StreamingAssets/aa/<Платформа>`: пустая папка означает, что мини-игра не загрузится вообще
- [ ] macOS: приложение не подписано, участник снимает карантин `xattr -dr com.apple.quarantine <путь>`, иначе система скажет «повреждено»
- [ ] Windows: SmartScreen «Подробнее» → «Выполнить в любом случае» + разрешение в брандмауэре

### Когда участникам обязательно перекачивать архив

Не «когда что-то поменялось», а по признакам — иначе гоняешь людей на гигабайт впустую:

| Что изменилось | Кому нужен новый билд |
|---|---|
| Сцена мини-игры (геометрия, расстановка) | **всем** — каждый грузит сцену из своего билда |
| Набор `NetworkVariable` у `NetworkBehaviour` | **всем** — иначе подключение развалится |
| Логика, исполняемая на машине игрока (блокировки, визуал, ввод) | **всем** |
| Только серверное решение (смена сцены, раздача ролей, подсчёт мест) | только хосту |

### Сбор результата

Лог билда — `~/Library/Logs/<Компания>/<Продукт>/Player.log` (macOS). Если инстансов несколько, живой пишет в `Player-prev.log`: логи проворачиваются при старте следующего, и дескриптор уходит за переименованным файлом. Проверять, какой файл открыт процессом, а не какой новее.

Найденное на прогоне заводить тикетами сразу, с симптомом и ролью пострадавшего игрока.
