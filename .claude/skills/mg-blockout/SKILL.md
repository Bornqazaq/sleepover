# Фаза 2 — Каркас (solo, серые блоки)

> **Модель: Opus 5.** Самая тяжёлая фаза: много кода, Unity MCP, длинная сессия. Opus 5 сильнее всего именно на многофайловой работе и доводит задачу до конца, а не оставляет заглушки. Если идёт пачка мелких правок и раздражает ждать — `/fast` (та же модель, быстрее выдача).

Цель: **игра полностью играется в одиночку и не содержит багов.** Геометрия — примитивы, материалов нет, сети нет. Вся логика уже настоящая.

Аргумент — название мини-игры или ID тикета.

## Железные правила фазы

1. **Network-ready с первой строки.** Каждый метод, меняющий важное состояние (урон, смерть, очки, места, старт/конец фазы, активация ловушки, спавн объекта), — единственная точка входа, которая в фазе 3 уйдёт за `IsServer` без переписывания. Состояние раунда — в одной структуре/классе, а не в разбросанных полях MonoBehaviour.
2. **Сначала Core, потом игра.** Прежде чем писать класс, проверить `Scripts/Core/` и `MinigameTemplate_HOWTO.md`. Если механика уже есть — использовать. Если пригодится второй игре — писать в Core.
3. **Никаких магических чисел.** Всё, что можно крутить, — в `MinigameDefinition` или `[SerializeField]` с понятным именем. Пользователь должен балансировать без меня.
4. **2–8 игроков.** Никакого хардкода под конкретное число.
5. Соблюдать `igruha/CLAUDE.md`: кэш компонентов в `Awake`, никаких `FindObjectOfType` в рантайме, физика в `FixedUpdate`, без аллокаций в update-циклах, Input System, asmdef не смешивать.

## Порядок работы

### 1. Развернуть каркас сцены (через Unity MCP)
По `Scenes/MinigameTemplate_HOWTO.md`, шаги 1–2:
- Скопировать `MinigameTemplate.unity` → `Scenes/Minigames/<Игра>.unity`
- Создать `MinigameDefinition` в `Settings/Gameplay/Minigames/`, заполнить числами из раздела 8 спеки (мин/макс игроков, длительность, категория, камера, тексты обучалки)
- Зарегистрировать сцену в Addressables, прописать адрес в конфиг

### 2. Арена из примитивов
`_Arena` — геометрия по разделу 3 спеки: кубы, плоскости, ProBuilder. Читаемо, но без красоты. `_Spawns` — точки под все роли (роль `Special` для асимметричных). `_Bounds` — `KillZone` под ареной.

### 3. Контроллер игры
Класс в `Scripts/Minigames/<Игра>/`, наследник `MinigameControllerBase`. Обязателен `CollectResults` — расставить места **всем** игрокам. Фазы — через `OnPlayersReady` / `OnRoundStarted` / `OnRoundEnded`, досрочный конец — `EndMinigame()`.

### 4. Механики по одной, с проверкой после каждой
После каждого блока кода:
```
refresh_unity → read_console (errors) → исправить → дальше
```
Не накапливать несколько непроверенных механик.

### 5. Соло-прогон
`PlayerSpawner.debugPlayerCount` — 1, потом 4, потом 8. Первый персонаж управляемый, остальные — болванки (для проверки толчков, попаданий, ловушек в одиночку).

Прогнать сценарии:
- игра доходит до экрана результатов;
- места расставлены всем, ничья обработана;
- игрок не может застрять, вывалиться из сцены навсегда, сломать состояние;
- раунд корректно кончается и по условию победы, и по таймауту;
- консоль чистая.

### 6. Отчитаться
Что построено, где лежит, что пользователю проверить руками в редакторе, какие числа стоит покрутить. Закрыть тикеты фазы, обновить `STATE.md`.

## Готово когда
- [ ] Игра проходится в одиночку от старта до результатов
- [ ] Работает на 2, 4 и 8 болванках
- [ ] Ноль ошибок и предупреждений от нашего кода в консоли
- [ ] Все настраиваемые числа вынесены в конфиг
- [ ] Ни одна механика не продублирована из Core
- [ ] Все точки изменения важного состояния собраны так, что фаза 3 их только обернёт
